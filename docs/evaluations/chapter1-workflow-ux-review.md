# Sample Networking PPTX 工作流与用户体验检查

测试对象：示例网络课程 Chapter 1 PPTX（原始本地文件名已泛化）

测试目标：检查当前 `ai-study-workflow` 在大学课程资料场景下，能否顺畅支持“新知识学习”和“期末复习”，并评估用户体验是否足够快、清晰、低负担。

## 1. 资料接入结果

PPTX 结构检查结果：

- 幻灯片数：89
- 备注页数量：86
- 媒体资源数量：109
- 稀疏文本页：4
- 图片/图示依赖较高页面：17
- 图形结构页面：2

抽样主题识别：

- 第 2 页：课程路线图
- 第 3 页：互联网组成视角
- 第 7 页：协议概念
- 第 21 页：主机发送分组、`L/R`
- 第 27 页：转发与路由
- 第 30 页：存储转发
- 第 35 页：分组交换与电路交换
- 第 48 页：时延组成
- 第 52 页：流量强度
- 第 56 页：吞吐量
- 第 71 页：协议栈
- 第 72 页：封装
- 第 84 页：总结
- 第 86 页：OSI 模型
- 第 89 页：Wireshark

判断：PPTX 的文本可读性明显好于之前测试的 PDF。当前流程可以直接建立章节地图、概念清单和练习题。但这份课件包含大量图示和媒体，单靠文本抽取仍会漏掉网络结构图、传输路径、协议栈封装示意等视觉信息。

## 2. 新知识学习模式检查

当前流程适合这份课件的地方：

- 先做资料地图，再进入学习任务，能避免一开始就陷入 89 页逐页总结。
- “预习检查 -> 分块讲解 -> 近迁移练习 -> 学生回答后反馈”的节奏适合计算机网络 Chapter 1。
- 对 `delay`、`throughput`、`traffic intensity`、`encapsulation` 这类概念，可以自然生成公式解释、情境题和反例。

主要体验问题：

- 首次输出如果同时给完整章节地图、学习计划、练习题、卡片建议，会过长。用户真正需要的是下一步动作。
- 课程第一章概念跨度大，从互联网组成、交换方式、时延、吞吐量到分层模型。新学模式如果按页推进，效率会低。
- 图片依赖页面较多，遇到网络结构图、协议栈图、路径图时，文本摘要不能替代视觉说明。

推荐的新知识学习入口：

```text
我识别到这是 Computer Networking Chapter 1，共 89 页，重点包括：
1. Internet/protocol 基本概念
2. network edge/core/access
3. packet switching、delay、throughput
4. protocol layers、encapsulation、security

建议先用 20 分钟建立骨架。
请先回答 4 个问题，我根据你的答案决定讲解深度：
1. 你能用一句话解释 protocol 吗？
2. packet switching 和 circuit switching 的核心差别是什么？
3. 你知道 nodal delay 包含哪几部分吗？
4. encapsulation 为什么需要分层？
```

结论：新知识模式可用，但首轮应从“短诊断 + 章节骨架”开始，而不是输出完整学习报告。

## 3. 期末复习模式检查

当前流程适合这份课件的地方：

- 能把 89 页拆成可复习的考试单元，而不是做普通摘要。
- 适合生成三类题：概念辨析题、公式计算题、场景解释题。
- “学生先答，AI 再评分”的规则可以防止复习变成被动阅读。

主要体验问题：

- 复习模式如果直接给 7 天计划，对临近期末的学生不一定最快。更好的第一步是 10 分钟快速诊断。
- Chapter 1 后半部分有 optional/additional slides，例如 OSI、Wireshark 相关内容，需要先询问是否在考试范围内。
- 题目难度需要分层，否则用户会被概念题、计算题、综合题混在一起打断。

推荐的复习入口：

```text
我先不讲内容，先测你哪里薄弱。
请用 10 分钟完成下面 8 题，只写关键词即可：
1. protocol 的三个要素是什么？
2. access network 和 network core 的区别是什么？
3. packet switching 为什么会产生 queueing delay？
4. store-and-forward 的总传输时间怎么算？
5. traffic intensity 接近 1 时会发生什么？
6. throughput 受哪些链路限制？
7. 五层协议栈各层职责是什么？
8. encapsulation 中 header 的作用是什么？
```

之后再输出：

- 错误归因：概念不清、公式不会、场景迁移弱、记忆缺口。
- 复习路线：只补薄弱点，不重学整章。
- 练习安排：先同型题，再变式题，最后小测。

结论：复习模式方向正确，但 UX 应改成“先诊断、后计划”，而不是“先计划、后学习”。

## 4. 工作流正确性检查

通过项：

- 先识别资料类型和质量，再选择学习/复习模式。
- 明确区分新知识学习和期末复习。
- 要求学生先回答，AI 再讲解或评分。
- 支持把资料转为知识地图、练习题、错因诊断和 Anki 卡片。
- 对视觉/稀疏/不确定内容有 `needs human check` 标记原则。

不足项：

- 目前 PDF 已有专门的检查和渲染工具，但 PPTX 还没有同等的一键检查脚本。
- PPTX 的备注页很多，当前流程没有显式规定“优先读取 notes 并标记教师强调内容”。
- 对图片密集页的处理还偏规则描述，缺少“自动渲染关键页 -> 识图 -> 合并到学习材料”的固定步骤。
- 输出层缺少长度控制，容易把一个学习助手做成一份长报告。

## 5. 用户体验判断

当前版本的核心能力是成立的，但默认交互还不够快。

学生视角下，最好的首屏不是报告，而是：

```text
资料已识别：
- Computer Networking Chapter 1
- 89 页，86 页有 notes，17 页需要看图
- 可直接学习，但图示页需要视觉检查

请选择：
1. 新学 2 小时：先建骨架，再做概念迁移
2. 考前复习：先做 10 分钟诊断，再只补弱点
3. 只生成材料：知识地图 / 题库 / Anki

建议：如果你要提效，先选 2，做诊断。
```

这个入口比直接输出长计划更快，也更符合“我要成效快的”。

## 6. 建议改进优先级

P0：增加 PPTX 资料检查脚本

- 输出 slide count、notes count、media count。
- 标记 sparse slides、image-heavy slides、formula-heavy slides。
- 生成章节地图和需要视觉检查的页面列表。

P0：增加 PPTX 渲染/识图步骤

- 对 image-heavy slides 渲染为图片。
- 用视觉模型读图，补充文本抽取遗漏的信息。
- 将视觉解释标记为 `visual-derived`，避免和原文混淆。

P1：优化首轮交互

- 首轮只输出资料卡、模式选择和一个最小任务。
- 不同时展开新知识和复习两套完整流程。
- 每次最多推进一个学习动作。

P1：复习模式增加 10 分钟诊断入口

- 先测 8-10 个代表题。
- 根据错误类型生成复习计划。
- 把计划压缩到薄弱点，而不是覆盖整章。

P2：新知识模式增加“骨架优先”

- 先讲章节主线。
- 再讲高价值概念。
- 最后做迁移题和卡片。

## 7. 总体结论

当前工作流在这份 PPTX 上是可用的，资料接入质量足以支持学习和复习。主要问题不是理解能力，而是用户体验：默认输出容易过长，学生需要更快进入“回答、被诊断、再补弱点”的循环。

下一版最值得做的是补齐 PPTX 检查与渲染工具，并把首轮体验改成“资料卡 + 三选一模式 + 立即开始的短任务”。
